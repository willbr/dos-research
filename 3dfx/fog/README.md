# Nave to graveyard: native Voodoo fog

A C / Glide 2.43 demo reusing the candlelit Winchester-inspired nave. The
camera travels through an open pointed west doorway, follows the path among
30 headstones and crosses, circles the graveyard's 15 trees, and returns to
the nave. The closed tour lasts approximately 100 seconds and uses an
arc-length lookup table for smooth travel. This is an original, approximate
scene, not a measured reconstruction of the cathedral grounds.

Run `./run.ps1` or `run.cmd`; rebuild with `./build.ps1`. The standard config
uses native emulated Voodoo Graphics: 2 MB framebuffer, one 2 MB TMU,
`voodoo_maxmem=false`, and no host Glide wrapper. It shares the vendored DOS
runtimes and compiler setup described in [the parent README](../README.md).

Manual look keeps the current indoor or outdoor position when leaving the
tour. Horizontal mouse movement and arrow turns follow camera-right rather
than the orbit sign. Walking uses a 1.7-unit eye height, 3 units/second speed,
basic wall/pillar/grave/trunk collision and wall sliding. It can traverse the
doorway freely. Free flight follows the look direction at 7 units/second,
with Space/Ctrl for vertical motion; it ignores geometry within a bounded world
volume. Shift doubles either speed. Diagonal inputs are normalized and movement
accelerates and brakes smoothly. Walking has no jump or gravity simulation;
it settles onto the ground height when selected. If switching from noclip inside
a solid footprint, it finds nearby clear ground or returns to the nave.

WASD uses IRQ1 make/break states, chained to the BIOS, so held movement and
release do not depend on typematic repeat. The handler is restored on exit.
Ordinary BIOS hotkeys remain available. Mouse look in first-person modes has
no release coasting; the drag-based manual mode retains flick inertia. Click
inside DOSBox-X to capture the mouse; Ctrl+F10 releases it.

In the shadows/detail descendants, WASD takes precedence over letter hotkeys:
Y toggles ground shadows, and T toggles the detail layer where present.
F returns to the automatic tour. Space pauses only outside first-person modes.
The active mode and relevant controls appear in the HUD. Free flight above the
nave uses conservative exterior visibility rather than the indoor portal shortcut.
The tour path stays clear of graves, trees and stonework.
The blending demo's G/C/M/L/S switches remain available for glass, candles,
sprite mist, light patterns and sorting. Sprite mist starts **off** here so
it does not mask the native distance-fog experiment.

## What the fog unit does

The demo downloads a 64-entry table with `grFogTable`, generated by
`guFogGenerateLinear`, `guFogGenerateExp` or `guFogGenerateExp2`.
`GR_FOG_WITH_TABLE` uses each vertex's reciprocal camera depth, interpolated
by the rendering pipeline. The framebuffer reciprocal Z and the TMU's
perspective UVs retain their existing roles. The fog factor does not consume
the alpha used for stained-glass transparency.

Ordinary opaque and alpha-blended surfaces use
`color = f * fogColor + (1-f) * surfaceColor`. Additive candle glows, flames
and floor-light patterns use `GR_FOG_WITH_TABLE | GR_FOG_ADD2`, which only
attenuates their contribution: `(1-f) * lightColor`. This avoids adding fog
color again with every light. Background and UI draw with fog disabled.
See the vendored Programming Guide, printed pages 63–68.

The stored mesh contains 5,074 triangles and 10,616 vertices, including both
detailed and coarse gravestone meshes. Only one level draws at a time. Gravestones
beyond 22 scene units use simplified geometry; trees retain their detail. Grass reuses the
unused roof texture slot; procedural stained glass and candle textures are
shared with `blending`. Total texture allocation, including profiler buffers,
is 991,232 bytes, within the standard 2 MB TMU. User-supplied photographs,
maps and plans were used only as references and were not saved.

Static bounds reject small nave groups and individual graveyard objects outside
camera visibility. Indoor views use the union of the doorway and window
openings; return views retain the outer facade and nave visible through the
door. Exact clipping handles partially visible quads. Distant headstones use
coarse geometry, including simpler caps and no tiny inscription bars.

Coincident positions share one transform per moving frame while keeping their
separate UVs and colors. Only referenced vertices are visited. Camera coordinates are copied from
the shared position cache only when clipping needs them. Constant face colors are batched through the color combiner instead of calculating RGB
triangle gradients. Coplanar pairs share quad clipping and the regular native
polygon API. Fog and the single TMU share identical reciprocal depth, avoiding
redundant W gradients. The HUD also uses constant-color text. CPU cycles,
hardware memory and graphics resolution are unchanged; all optimizations are C.

## Validation and performance

Run `./verify.ps1` for OpenGL scene checks and software Voodoo fog controls.
Run `./soak.ps1` separately for a 1,440-frame journey, half with the profiler
visible. Add `-FullTour` for 6,000 frames covering the entire 100-second route
at 1/60-second increments. Both tests fail on any guest frame over 18 ms or
Windows throughput below 59.5 FPS. The benchmark measures actual Windows
wall-clock FPS as well as recording guest timings; avoid running another demo during that measurement.

Sixteen framebuffer controls test zero/half/full fog, disabled fog, independent
alpha blending, additive attenuation, and all three generated curves at
depths 4, 16 and 48. Both OpenGL and software Voodoo pass. RGB565 dithering
and backend rounding are allowed a 12/255 tolerance per channel.

Scene checks capture fog on/off views in the nave, at the doorway and in the
graveyard. Culled and unculled images must match exactly at all 16 camera
keys. The route is independently checked at 8,192 positions for doorway,
aisle and grave clearance, and manual/tour switching is checked indoors and
outdoors. Quad/triangle and constant/iterated-color comparisons additionally
check four representative views. They allow at most 220 scene pixels with a
channel difference over 16/255 to accommodate subpixel diagonal/edge rounding;
constant-color checks currently have zero such pixels. Captures and logs are
local, ignored test outputs.

The original larger scene measured 48.39 Windows FPS, with 344 of 1,440 guest
frames over 18 ms. The optimized 1,440-frame soak measured **59.98 Windows
FPS** (24.009 seconds), **60.04 guest FPS**, a **17.213 ms** maximum guest
frame, and **zero frames over 18 ms**, including the moving camera and the
profiler. The [lightmap demo](../lightmap/README.md) uses the same renderer
and adds native lightmapping within that frame budget; its full 6,000-frame
tour also passes.
The live FPS counter uses the guest clock; assess actual host throughput with
the Windows-clock benchmark.
